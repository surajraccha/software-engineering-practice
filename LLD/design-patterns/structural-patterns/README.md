# Structural Patterns

[Back to design patterns](../README.md)

This module is for practicing patterns that describe how classes and objects are composed.

## Patterns To Practice

| Pattern | Purpose |
| --- | --- |
| [Adapter](src/main/java/patterns/structural/adapter/PACKAGE.md) | Make incompatible interfaces work together. |
| [Bridge](src/main/java/patterns/structural/bridge/PACKAGE.md) | Separate abstraction from implementation. |
| [Composite](src/main/java/patterns/structural/composite/PACKAGE.md) | Treat individual objects and object groups uniformly. |
| [Decorator](src/main/java/patterns/structural/decorator/PACKAGE.md) | Add behavior without changing the original class. |
| [Facade](src/main/java/patterns/structural/facade/PACKAGE.md) | Provide a simple interface over complex subsystems. |
| [Flyweight](src/main/java/patterns/structural/flyweight/PACKAGE.md) | Share reusable state to reduce object cost. |
| [Proxy](src/main/java/patterns/structural/proxy/PACKAGE.md) | Control access to another object. |

## Practice Template

For each pattern:

1. Add a package named after the pattern.
2. Show the problem without the pattern.
3. Show the improved design with the pattern.
4. Document tradeoffs in the package notes.
