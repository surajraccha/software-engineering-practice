# Structural Patterns

[Back to design patterns](../README.md)

This module is for practicing patterns that describe how classes and objects are composed.

## Patterns To Practice

| Pattern | Purpose |
| --- | --- |
| Adapter | Make incompatible interfaces work together. |
| Bridge | Separate abstraction from implementation. |
| Composite | Treat individual objects and object groups uniformly. |
| Decorator | Add behavior without changing the original class. |
| Facade | Provide a simple interface over complex subsystems. |
| Flyweight | Share reusable state to reduce object cost. |
| Proxy | Control access to another object. |

## Practice Template

For each pattern:

1. Add a package named after the pattern.
2. Show the problem without the pattern.
3. Show the improved design with the pattern.
4. Document tradeoffs in the package notes.
