# Behavioral Patterns

[Back to design patterns](../README.md)

This module is for practicing patterns that organize communication and responsibility between objects.

## Patterns To Practice

| Pattern | Purpose |
| --- | --- |
| Chain of Responsibility | Pass a request through handlers until one handles it. |
| Command | Encapsulate a request as an object. |
| Iterator | Traverse a collection without exposing internals. |
| Mediator | Reduce direct dependencies between objects. |
| Memento | Capture and restore object state. |
| Observer | Notify dependents when state changes. |
| State | Change behavior when internal state changes. |
| Strategy | Swap algorithms behind a common interface. |
| Template Method | Define an algorithm skeleton with customizable steps. |
| Visitor | Add operations to object structures without changing their classes. |

## Practice Template

For each pattern:

1. Add a package named after the pattern.
2. Explain the collaboration between objects.
3. Add a demo flow in code.
4. Document where the pattern is useful and where it may be too much.
